# 人脉知识库系统 - Product Requirement Document

## Overview
- **Summary**: 面向个人销售（CCTV《大国品牌》销售场景）打造的「人脉资源管理 + 关系网络图谱」一体化工具。核心回答三个问题：我认识谁、谁能帮我链接谁、我最近该联系谁。系统支持人物档案管理、多维度标签分类、关系网络可视化图谱、互动跟进记录、业务机会跟踪以及 Excel/CSV 批量数据导入。
- **Purpose**: 解决个人销售在人脉管理中的三大痛点：1) 人脉信息分散（微信/通讯录/笔记各存一部分）；2) 无法看清人脉之间的链接关系，错失资源撮合机会；3) 缺乏系统化跟进机制，重要关系久未维护导致生疏。
- **Target Users**: B2B 销售、商务拓展人员、资源中介、需要管理复杂人脉网络的独立从业者。

## Goals
- 建立完整可检索的人物档案库，支持多标签、多维度筛选
- 实现一度/二度关系网络可视化图谱，直观展示人脉链接与引荐链
- 建立互动跟进体系，记录每次沟通并支持回溯
- 支持 Excel/CSV 批量导入，降低初始使用门槛
- 移动端响应式设计，满足饭局/外出场景快速录入需求

## Non-Goals (Out of Scope)
- 不做团队协作/多租户权限系统（仅个人单账号使用）
- 不做复杂的营销自动化（邮件群发、定时消息等）
- 不做第三方 IM 集成（微信/钉钉消息自动同步）
- 不做 AI 智能问答模块（三期再考虑）
- 不做电话拨打、短信发送等通信能力

## Background & Context
- **业务场景**: 用户为 CCTV《大国品牌》栏目销售人员，核心工作是链接品牌方资源，促成品牌与央视栏目的合作。人脉覆盖品牌方市场部负责人、广告代理公司、媒体圈、投资圈等，人脉之间存在大量引荐关系和交叉链接。
- **技术决策**: 
  - 前端 React + Ant Design 组件库，确保开发效率和 UI 一致性
  - 后端 Node.js + Express，前后端语言统一降低维护成本
  - SQLite 作为数据库，零配置、单文件存储，适合个人使用场景，便于备份迁移
  - 关系图谱使用 ECharts Graph，文档完善、交互能力强，与 React 集成简单
- **UI 设计原则**: 现代简洁风，参考 Notion / Linear 设计语言。浅色主题、大量留白、卡片式布局、柔和的阴影层次、主色调采用专业蓝紫系。

## Functional Requirements

### FR-1: 人物档案管理
- 支持人物档案的新增、编辑、删除、查看详情
- 基础信息字段：姓名（必填）、电话、微信、邮箱、生日、城市、公司、职位
- 分类标签：支持多选（亲戚/同学/朋友/合作伙伴/客户/老公亲戚/老公同事/其他自定义标签）
- 亲密度分级：1-5 星（★~★★★★★）
- 资源描述：多行文本，记录该人能提供的资源/能力
- 需求描述：多行文本，记录该人可能的需求/痛点
- 私域备注：多行文本，记录忌口、家庭情况等私密信息
- 头像支持：默认首字母头像，可上传自定义头像

### FR-2: 标签管理与筛选
- 支持按标签筛选人物列表（可多选标签，AND/OR 逻辑切换）
- 支持按亲密度筛选
- 支持按城市、公司关键字筛选
- 全局搜索：姓名、公司、职位、资源描述、需求描述全文模糊搜索
- 人物列表支持按亲密度、最近联系时间、创建时间排序

### FR-3: 关系网络管理
- 支持为任意两个人之间建立关系链接
- 关系类型：大学同学、高中同学、同事、前同事、夫妻、亲属、朋友、合作伙伴、引荐、客户、其他自定义
- 引荐链：记录"X 是经由 Y 介绍的"，支持追溯人脉来源
- 关系强度：1-5 级（影响图谱节点距离）

### FR-4: 关系图谱可视化
- 以选中人物为中心，展示一度人脉（直接关系）和二度人脉（朋友的朋友）
- 节点大小与亲密度正相关
- 节点颜色按标签分类区分（不同标签不同颜色）
- 连线类型/粗细表示关系类型和强度
- 点击节点：跳转到该人物详情页，或以该节点为中心重新展开图谱
- 支持拖拽布局、缩放、全屏查看
- 悬停节点显示人物基本信息卡片（姓名、公司、职位、亲密度）

### FR-5: 互动记录管理
- 支持为每个人物新增互动记录
- 互动字段：日期（必填）、方式（微信/电话/面谈/饭局/活动/其他）、内容（多行文本）、待办事项
- 待办事项支持勾选完成状态
- 人物详情页按时间倒序展示互动历史
- 互动记录可编辑、删除

### FR-6: 业务机会管理（二期功能，一期保留数据结构）
- 业务机会字段：机会名称、关联人物、关联公司、当前阶段（初谈/提案/报价/签约/执行/结案/流失）、预计金额、预计签约时间、备注
- 人物详情页展示关联的业务机会列表
- 阶段变更记录保留历史

### FR-7: 提醒与待办
- 生日提醒：提前 7 天 / 3 天 / 1 天显示即将过生日的人
- 久未联系提醒：超过 90 天 / 180 天 / 365 天未互动的人，按亲密度分级提示
- 首页 Dashboard 展示：今日待联系、近期生日、超期未联系、待办事项汇总

### FR-8: Excel/CSV 数据导入
- 支持上传 Excel (.xlsx, .xls) 和 CSV 文件
- 提供标准导入模板下载（预定义列名与格式）
- 导入前数据预览：展示前 20 行数据，用户可确认/取消
- 字段映射：支持用户手动将文件列映射到系统字段
- 重复检测：按姓名+电话组合去重，支持跳过/覆盖/新增三种策略
- 导入结果报告：成功数、跳过数、失败数、失败原因明细

### FR-9: 数据导出
- 支持人物数据导出为 Excel
- 支持互动记录导出
- 导出格式与导入模板兼容，形成闭环

### FR-10: 账户与安全
- 本地账号密码登录（无需注册流程，首次启动初始化管理员账号）
- 数据库文件支持手动备份 / 恢复
- 所有页面需登录后访问

## Non-Functional Requirements
- **NFR-1 响应式设计**: 支持桌面端（≥1280px）、平板（≥768px）、手机（≥375px）三种断点，手机端为主力使用场景需重点优化录入体验
- **NFR-2 性能**: 人物数据 ≤ 5000 条时，列表加载 < 1s，图谱渲染 < 2s
- **NFR-3 数据安全**: 数据库文件定期备份机制，支持导出为加密 zip
- **NFR-4 可用性**: 单个页面录入操作 ≤ 3 步完成，饭局场景 30 秒内完成一条人物录入
- **NFR-5 可维护性**: 前后端分离，RESTful API 设计，代码注释完整，数据库表结构文档齐全

## Constraints
- **Technical**:
  - 前端：React 18 + React Router 6 + Ant Design 5 + ECharts 5 + Zustand 状态管理
  - 后端：Node.js 18+ + Express 4 + better-sqlite3（同步 SQLite 驱动，性能优异）
  - 构建工具：Vite
  - 不允许使用重型 ORM（如 TypeORM），直接使用 SQL 或轻量查询构建器以保证性能和可控性
- **Business**:
  - 一期开发周期目标 7-10 个工作日完成可用 MVP
  - 仅服务单用户，无需权限分级
- **Dependencies**:
  - Excel 解析：xlsx (SheetJS)
  - 密码加密：bcryptjs
  - 文件上传：multer
  - 日志：winston

## Assumptions
- 用户在 Windows / Mac 本地环境运行，具备基础的命令行操作能力（启动 npm 脚本）
- 人脉数据量级在 100~5000 人范围内，SQLite 完全可以支撑
- 用户自行负责数据备份，系统提供手动导出备份功能即可
- 一期不需要手机原生 App，移动端浏览器（微信内置浏览器 / Safari / Chrome）访问即可

## Acceptance Criteria

### AC-1: 人物档案完整增删改查
- **Given**: 用户已登录系统
- **When**: 用户在人物列表页点击「新增人物」，填写必填字段并保存
- **Then**: 人物档案创建成功，列表中立即显示，详情页字段完整可查看；编辑和删除操作同样可正常执行，删除需二次确认
- **Verification**: programmatic

### AC-2: 多维度筛选与搜索
- **Given**: 系统中已有 100+ 条人物数据，覆盖多个标签、城市、亲密度
- **When**: 用户选择标签（如"合作伙伴"+"客户"）并设置亲密度 ≥3 星，或在搜索框输入公司关键字
- **Then**: 列表实时过滤，结果符合筛选条件；清除筛选条件后恢复全量列表
- **Verification**: programmatic

### AC-3: 关系建立与图谱展示
- **Given**: 已创建人物 A、B、C，并建立关系：A-大学同学-B，B-引荐-C
- **When**: 用户进入图谱页选择人物 A 为中心
- **Then**: 图谱显示 A 为中心节点，B 为一度节点通过「大学同学」连线连接，C 为二度节点通过 B 引荐链展示；节点颜色按标签区分，大小按亲密度区分；悬停节点显示信息卡片
- **Verification**: human-judgment

### AC-4: 互动记录时间线
- **Given**: 人物 X 已有 3 条互动记录（不同日期）
- **When**: 用户打开人物 X 详情页，并新增一条互动记录
- **Then**: 互动记录按时间倒序排列，新记录在最顶部；待办事项可勾选切换完成状态
- **Verification**: programmatic

### AC-5: 首页 Dashboard 提醒
- **Given**: 系统中存在 3 天内过生日的 2 人、180 天未互动的 5 人、未完成待办 3 条
- **When**: 用户登录系统进入首页
- **Then**: Dashboard 分区展示「近期生日」「超期未联系」「待办事项」「最近互动」四个模块，数据准确对应
- **Verification**: programmatic

### AC-6: Excel 导入流程
- **Given**: 用户下载了标准模板，填写了 50 条人物数据（其中 2 条与现有数据重复）
- **When**: 用户上传文件 → 预览数据 → 确认字段映射 → 选择重复策略为「跳过」→ 点击导入
- **Then**: 导入完成后显示报告：成功 48 条、跳过 2 条、失败 0 条；列表中可查询到新导入的 48 人
- **Verification**: programmatic

### AC-7: 移动端录入体验
- **Given**: 用户使用手机浏览器（宽度 375px）访问系统
- **When**: 用户点击「快速录入」填写姓名、电话、标签、备注并保存
- **Then**: 表单适配手机屏幕宽度，无横向滚动；输入框弹出键盘不遮挡提交按钮；30 秒内可完成一条基础录入
- **Verification**: human-judgment

### AC-8: 登录与数据安全
- **Given**: 系统已初始化管理员账号
- **When**: 用户未登录直接访问任意 URL，输入错误密码，输入正确密码
- **Then**: 未登录一律跳转到登录页；错误密码提示「账号或密码错误」；正确密码跳转到首页并保持登录状态（会话过期需重新登录）
- **Verification**: programmatic

### AC-9: 数据导出闭环
- **Given**: 系统中有 100 条人物数据和若干互动记录
- **When**: 用户分别导出人物 Excel 和互动记录 Excel
- **Then**: 导出的 Excel 可正常打开，字段齐全；导出的人物文件可直接用于重新导入（列名与模板一致）
- **Verification**: programmatic

### AC-10: 图谱交互流畅
- **Given**: 图谱页面已渲染 100 个节点 + 150 条连线
- **When**: 用户拖拽节点、缩放画布、点击节点跳转、全屏切换
- **Then**: 操作无明显卡顿（≤300ms 响应），节点位置不错乱，信息卡片正常弹出
- **Verification**: human-judgment

## Open Questions
- [ ] 业务机会模块是否需要一期提前实现？（当前规划为二期，但对销售场景可能很重要）
- [ ] 标签是否需要支持嵌套层级？（如「同学→大学同学→XX级」，当前设计为扁平标签）
- [ ] 是否需要「快速添加关系」的批量操作？（如一次性把某场活动加的人全部互设为「活动结识」关系）
- [ ] 数据库自动备份频率？（当前设计为手动备份，是否需要每日/每周自动备份）
